# 《编码：隐匿在计算机软硬件背后的语言》 — 查尔斯·佩措尔德（Charles Petzold）
> 类型：论说 | 原文规模：约 15.9 万字 | 抽样依据（工作档案 udigest/214.md（6 段）

## 一句话
从莫尔斯码讲到操作系统，示范每一层抽象该切在哪、接口该定成什么。

## R｜原文骨架
- 第 1–3 章 至亲密友、编码与组合、布莱叶盲文 → 编码的基本观念：码字、前缀、以 2 为底的容量。
- 第 4–6 章 手电筒、绕过拐角的通信、电报机与继电器 → 从电路走到逻辑，继电器是第一个"会判断"的零件。
- 第 7–10 章 我们的十个数字、十的替代品、二进制数、逻辑与开关 → 进制与布尔代数，为门电路准备数学。
- 第 11–17 章 门、加法器、如何实现减法、反馈与触发器、存储器组织、自动操作 → 组合电路到时序电路，拼出可编程机器。
- 第 18–25 章 从算盘到芯片、两种微处理器、ASCII、总线、操作系统、浮点数、高级与低级语言、图形化革命 → 系统层的设备、编码与调度。

## I｜核心命题与可执行方法
**先数容量，再定码长** —— 触发：要设计一套编码、协议或 ID 体系。动作：算 2 的 n 次幂够不够放下全部条目并留余量；用树形结构组织码字，保证任一码字都不是另一个的前缀。验收：解码无歧义，且高频项拿到短码。莫尔斯码表就是一棵树，"点-划-点"沿树走到 R。

**只在相邻两层之间定契约** —— 触发：系统复杂到没人能整体讲清。动作：为每层写一张契约（输入、输出、真值表或时序），禁止跨层调用。验收：每层可单独验证，替换一层不影响其他层。器件换代时先用这条比对：接口未变，则迁移成本集中在最底层，上层软件可整体沿用——4004 只有 2300 个晶体管，三十年后家用 CPU 逼近 1000 万个，"所做的工作一直没有变"。

**换一种表示，能省掉一半硬件** —— 触发：两个功能各需一套专用电路。动作：找数学变换让它们共用同一套硬件。验收：硬件减少而结果不变，且溢出、符号等边界情况有交代。用补码把减法变成加法，是全书最干净的一例。

**反馈把组合电路变成有状态的机器** —— 触发：需要记忆、计数、按时序动作。动作：把输出接回输入，加时钟或使能端控制写入时机。验收：能稳定保持一位，可置位、可复位，且输入抖动不会穿透到输出。

**给设备做一个统一插座** —— 触发：每加一类外设就要改上层程序。动作：定义统一的代码与地址约定（ASCII、端口、总线），把差异压进适配层。验收：换设备只换适配层，上层代码不动。

## A1｜书中实例
- 第 2 章：用莫尔斯码表说明编码规律——每多一个"点"或"划"，可表示的码字数翻倍，即 2 的（点和划的数目）次幂；并画出树形图，按"点—划—点"查找，得到字母 R。
- 第 10 章：用猫的集合解释布尔代数，B+W 是所有黑猫与白猫的并集，F×T 是褐色母猫的交集；并指出布尔代数中加法可以分配乘法：W+(B×F)=(W+B)×(W+F)。
- 第 16 章：搭出 8192 比特、每 8 比特一组共 1024 组的 RAM 阵列，地址端 10 个，于是容量等于 2 的地址端个数次幂。作者顺带解释 1K 等于 1024 而非 1000，因为"不存在一对整数a和b使得10的a次幂与2的b次幂相等"。

## A2｜何时调用 / 与相邻书的区分
- 用户要给非计算机专业的人解释"计算机到底怎么工作"时，按编码—逻辑—存储—系统的顺序讲。
- 用户要设计编码、协议字段或设备接口时，用"先数容量"与"统一插座"。
- 用户判断某个抽象层该放什么时，用相邻层契约。
- 用户把一次硬件换代说成"一切重来"时，先比对各层接口是否变化。
- 与《C Primer Plus》同讲底层：那本给语法与工程约定，是"怎么写"；本书给概念链，是"为什么长成这样"。
- 与《芯片简史》同讲硬件演化：那本讲工艺约束下的路线选择，本书讲逻辑与抽象如何一层层搭起来。

## E｜执行步骤
1. 输入一个待拆解的系统或待设计的编码。动作：列出符号集与操作集。产出：符号表与操作表。
2. 动作：算容量——2 的 n 次幂能否覆盖，是否留余量与前缀约束。产出：码长方案与冲突检查。
3. 动作：画层级图，为相邻两层各写一张契约。产出：分层接口表。
4. 动作：检查是否有两个功能可合并为一种表示（如减法并入加法）。产出：可合并项与边界清单。
5. 动作：做"换层测试"，替换某一层看上层是否要改。产出：耦合点清单与重构建议。

## B｜边界与误用
- 成书于 1999 年前后，不涉及多核、GPU、网络协议栈与现代操作系统；拿它解释今天的机器会缺一大块。
- 例子以 8080 与早期 x86 为主，具体电路与指令已过时，只有分层方法仍有效。
- 全书几乎不谈性能、成本、可靠性的取舍，也不讲团队与维护，不能当架构决策依据。
