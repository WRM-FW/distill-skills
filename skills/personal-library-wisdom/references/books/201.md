# 《C Primer Plus》 — 斯蒂芬·普拉塔（Stephen Prata）
> 类型：论说 | 原文规模：约 48.0 万字 | 抽样依据（工作档案 udigest/201.md（6 段）

## 一句话
用声明与定义、链接属性、访问模式三件事，把 C 程序的复杂度按层切开并逐层验收。

## R｜原文骨架
- 第 1–2 章 初识 C、C 语言概述 → 编译—链接—运行的链条，并用"两遍读法"逐行拆第一个程序。
- 第 3–4 章 数据与字符串格式化输入输出 → 类型、常量、printf/scanf 的匹配规则。
- 第 5–8 章 运算符、循环、分支、字符 I/O 与输入验证 → 控制流，以及读失败如何处理。
- 第 9–12 章 函数、数组与指针、字符串、存储类别与链接 → 作用域、链接属性、地址与内存布局，全书重心。
- 第 13–14 章 文件输入输出、结构和其他数据形式 → 位字段把外部格式映射成类型（14 章 fields.c）。
- 第 15–17 章 位操作、预处理器与 C 库、高级数据表示 → 抽象数据类型；17.7 节用二叉树做成员名册。

## I｜核心命题与可执行方法
**接口与实现分家：头文件只放声明** —— 触发：两个以上源文件要用同一函数。动作：原型与宏进 .h，定义进 .c；标准库用尖括号，本地头文件用双引号让编译器先查当前目录。验收：改实现不用改调用方，链接一次通过；头文件里出现函数体，就是分层失败。

**用链接属性划封装边界** —— 触发：模块间出现同名符号，或某个变量被意外共享。动作：默认给函数与文件级变量加 static，确需跨文件才用 extern 并在头文件声明。验收：符号表里没有计划外的全局名；这一步做对，重构才不会连带炸掉别处。

**按访问模式选数据结构** —— 触发：要在一批记录上频繁查找、插入、删除。动作：先数操作配比——查多且有序用数组加二分；增删频繁且位置不定用链表；既要有序又要常查常插用二叉树。验收：能写出最坏情况下单次操作的代价，而不是只说"用了链表"。数组大小用符号常量（第 10 章 `#define MONTHS 12`），改一处即可全局生效。

**位字段直接映射外部格式** —— 触发：数据要按位对齐协议字段或硬件寄存器。动作：照手册的顺序与宽度声明位字段，空位用无名位字段补齐，同时记住布局是实现定义。验收：sizeof 与各字段位置在目标编译器上与规范一致；换平台前必须实测，不能把结构体直接当线格式。第 14 章 fields.c 的 `box_props` 即此写法。

**读失败必须消费掉坏字符** —— 触发：在循环里用 scanf 读用户输入。动作：检查返回值，失败时清空输入缓冲再继续。验收：输错一次只报一次错；否则会得到"无限失败的循环"，程序空转而不退出。

## A1｜书中实例
- 第 2 章「第 2 遍：程序细节」逐行拆程序清单 2.1：`#include <stdio.h>` 相当于把整个头文件"输入该行所在的位置"，作者称之为"拷贝-粘贴"；头文件只帮编译器正确组合程序，函数代码在预编译的库文件里。
- 第 6 章讲关系运算符：作者提醒"不要在本应使用==的地方使用="，编译器不报错、只给错误结果；对策是把常量写在左侧，因为 C 不允许给常量赋值，写错就成了语法错误。
- 第 17 章 DeleteNode：删除分三种情形，被删节点有两个子节点时，先找左子树最右端，再把右子树接上去——改指针而不搬数据。

## A2｜何时调用 / 与相邻书的区分
- 用户要写或审一段 C，尤其是多文件工程、头文件组织、static/extern 用法时。
- 用户在数组、链表、二叉树之间选型，需要按操作配比决定时。
- 用户判断一段 C 能否移植（位字段、类型宽度、字节序）时。
- 用户的输入循环"输错就卡死"时，用读失败那条。
- 与《编码》同讲底层：那本从继电器与逻辑门推到高级语言，给概念地图；本书给语法、库与工程约定。先读《编码》建层级感，再用本书落地。

## E｜执行步骤
1. 输入一个 C 程序或设计草案。动作：画出文件划分，标出每个符号的可见范围。产出：模块—符号表。
2. 动作：核对头文件是否只有声明、实现是否都在 .c、默认是否 static。产出：封装问题清单。
3. 动作：列出核心数据结构的操作配比（查/插/删/遍历次数）。产出：选型结论与最坏代价估算。
4. 动作：检查所有输入读取点的返回值与缓冲清理，检查位字段与外部格式的对应。产出：健壮性与可移植性缺陷表。
5. 动作：按缺陷表改一处、编译一次、跑一个最小用例。产出：可复现的修复记录。

## B｜边界与误用
- 这是语言教材，不教构建系统、调试器、并发、内存检测；真实工程的坑大半在书外。
- 位字段布局、char 是否有符号、整数宽度都是实现定义，书中示例只能证明"在某编译器上成立"。
- 书中以标准语法与例题为主，性能优化、缓存行为、未定义行为的系统梳理都不深。
