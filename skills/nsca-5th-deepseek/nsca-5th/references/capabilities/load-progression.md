# 负荷进阶（何时加：2-for-2；加多少：增幅 / 重轻日变异）

## R — 原文 (Reading)

> "If the athlete can perform 2 or more repetitions over his or her assigned repetition goal for a given exercise in the last set in two consecutive workouts, weight should be added to that exercise for the next training session."

— Chapter 18 · Step 5: Timing Load Increases（`ch18.txt` 1957–1959）

## I — 自述 (Interpretation)

负荷进阶回答两个问题：**何时加**与**加多少**。

**何时加——2-for-2 规则（保守法）**：若运动员在**连续两次训练**的**最后一组**中，某动作比分配的目标次数**多做 ≥2 次**，则下一次训练为该动作加负荷。示例：卧推指派 3×6，末组连续两次各完成 8 次 → 下次加负荷。
- **局限（作者明确警告）**：2-for-2 不考量技术、阶段目标、相对强度，长期可能导向力竭；若靠改技术凑次数则不应加；若阶段是**故意留 RIR** 的额外次数，也不算加负荷信号。

**加多少——Table 18.12（分强弱、分上下肢）**：较弱/训练少：上肢 2.5–5 lb（1–2 kg），下肢 5–10 lb（2–4 kg）；较强/训练多：上肢 5–10+ lb（2–4+ kg），下肢 10–15+ lb（4–7+ kg）；SRB 统一约 5%/周。差异大时可用**相对增幅 2.5%–10%** 替代绝对值。增幅须匹配具体动作、负荷形式（自由重量/弹力带/哑铃）与进阶方法（%1RM/RPE/RIR/SRB）。

**重/轻日变异（周内）**：每周只设一个（至多两个）heavy day，重日负荷高但留 **1–2 RIR** 不练到力竭；轻日用重日负荷的 **80%**、次数不变。可推广到任意频率；与专项训练轻重错配（重举日配轻专项日）；须监控避免"天天重"。

## A1 — 案例 / 演练 (Application)

**原书案例（worked-example，c18-9）**：卧推指派 3×6，运动员在第三（末）组连续两次训练各完成 8 次（超目标 2 次）→ 下次训练加负荷。原文提示此法最终可能诱导力竭，需权衡技术。

**原书案例（tabular-example，c18-10 / Table 18.12）**：给出"较弱/较强 × 上肢/下肢"的绝对与相对增量，可用 2.5%–10% 相对增量替代。

**合成演练（标记：合成；非书中案例）**
- 输入：卧推指派 3×6；连续两次末组各完成 8 次、技术稳定；运动员属"较强、上肢"。
- 执行：满足 2-for-2 → 下次加负荷；增幅按较强上肢取 **+5–10 lb**（或用 2.5%–10% 相对）。
- 预期输出：加 +5–10 lb。若靠变技术凑数则不加。原书未说明该合成输入的"实际结果"。

## A2 — 未来触发 (Trigger)

**用户会遇到这类问题的情境（3–5 条）**
- 用户问"运动员什么时候可以加重、一次加多少"。
- 用户说运动员连续两次都多做了一两次，问要不要加。
- 用户问负重方案一成不变、想对抗单调与疲劳，问怎么安排重/轻日。
- 用户问轻日该用多少负荷。
- 用户问靠改技术凑次数算不算可以加负荷。

**语言信号（中英双写关键 trigger 词）**
- "什么时候加重" / "progression"、"load progression"、"2-for-2"、"加多少磅"、"负荷增幅"、"table 18.12"、"重日轻日"、"heavy/light day"、"轻日 80%"、"留 RIR"、"能不能加负荷"、"练了两次都超次数了"。
- 英文常见："when should I increase the load"、"how much to add"。

**与相邻能力的区分（初稿）**
- 与 **load-reps-assignment**：后者定"当前用多重"，本卡定"何时、加多少"。
- 与 **rpe-rir-srb-load**：SRB 的 5% 递进与 2-for-2 同为进阶口径，但本卡以 2-for-2 为判据。
- 与 **training-volume**：重/轻日变异只调负荷不调次数，量由后者承载。
- 与 B-periodization 簇：跨周/中周期的减量周（deload）编排属周期化（p18-03 判 reference，注明由 B 簇承载）；本卡只保留**周内**重/轻日 80% 变异。

## E — 执行 (Execution)

**输入契约**
- 必需：目标次数、连续两次训练的末组实际次数、技术稳定性、阶段是否故意留 RIR；运动员强弱与部位（用于查 Table 18.12）。
- **先询问（缺失不得静默猜值）**：若无"连续两次末组实际次数"记录 → 无法判 2-for-2，先要训练记录；若技术稳定性未知 → 询问或观察（凑数变形则不加）；若强弱/部位未知 → 询问以选增幅档。
- 适用条件：适用于有训练记录者；2-for-2 主要面向 novice 起量，注意其局限。

**步骤（每步有完成标准）**
1. **判"何时加"（2-for-2）**——完成标准：核对连续两次训练末组是否均超目标 ≥2 次。判停点：若技术靠变形凑数，或阶段故意留 RIR 才多做 → **不加**。
2. **定"加多少"**——完成标准：按强弱×部位查 Table 18.12 绝对增幅（较弱上肢 2.5–5 lb｜较弱下肢 5–10 lb｜较强上肢 5–10+ lb｜较强下肢 10–15+ lb）；差异大时改用 **2.5%–10%** 相对增幅。SRB 法取约 5%/周。
3. **匹配动作/负荷形式/进阶方法**——完成标准：增幅注明针对的动作与加载方式，与所选进阶方法（%1RM/RPE/RIR/SRB）一致。
4. **（可选）设计重/轻日变异**——完成标准：每周仅 1 个（至多 2 个）heavy day，重日留 1–2 RIR；轻日＝重日 **80%** 负荷、目标次数不变；与专项训练日轻重错配；不得天天重。判停点：即使能做更多次数也不得超过目标次数。
5. **交付**——完成标准：输出 `{ 是否加负荷, 增幅(绝对值或%), 重/轻日安排 }`。

**输出契约**
- 字段：`{ add_load(bool), increment(lb/kg 或 %), rationale, heavy_light_plan }`。
- 数值：绝对增幅照 Table 18.12 档位；相对增幅 2.5%–10%；SRB 5%/周。
- 约定：「较弱/较强」为主观二分，原文未与训练状态三档直接映射；80% 为示例值（其他处 80%–85%）。

## B — 边界 (Boundary)

- **不要**机械套用 2-for-2——它不考量技术、阶段目标与相对强度，可能导向力竭；靠改技术凑次数时不得加负荷。
- **不要**在**故意留 RIR** 的阶段把额外次数当作加负荷信号。
- **不要**"天天重"——每周只设 1 个（至多 2 个）heavy day，须监控。
- **共识 ≠ 实证**（BOOK_OVERVIEW 3.3-5）：Table 18.12 的增幅与 80% 轻重比来自实践惯例（约 3×5–10 次计划），跨程序迁移无保证。
- **变量耦合**（3.3-3）：改负荷会牵动量、休息与技术。
- 易混淆：与 **load-reps-assignment**（当前负荷）、**rpe-rir-srb-load**（SRB 递进口径）、B-periodization（减量周）不同——本卡只处理"周内何时加、加多少"。
