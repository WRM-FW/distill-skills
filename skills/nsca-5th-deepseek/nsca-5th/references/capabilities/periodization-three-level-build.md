# 周期化的三级建立流程（周期化 → 规划 → 编程）

## R — 原文 (Reading)

> "periodization serves as the macro-management level of the training process, while programming allows for the micro-management of the process. Conceptually, periodization serves as a method for organizing deliberate practice by providing the scaffold from which programming decisions are made."

— Chapter 22 · Periodization and Planning the Training Process（`ch22.txt` 第 44–63 行）

## I — 自述 (Interpretation)

周期化（periodization）与编程（programming）不是同义词，而是同一训练过程的**两个管理粒度**：前者管宏观方向与结构，后者管微观内容与微调。原书把它落成一条自上而下、三层相互依赖的建立流程（Table 22.1）：

1. **一级 · periodization（宏观）**：以竞赛日程为输入，把年度/多年计划切成时期与阶段，搭出"脚手架"。它只定方向与框架，不定具体重量。
2. **二级 · planning（宏观）**：在框架内选定一个训练模型（parallel / sequential / emphasis）来指导后续决策。
3. **三级 · programming（微观）**：把模型与各时期阶段对齐，落地真正的 modes、methods、负荷（强度/量）与训练结构（负荷模式、组类型），并接监测数据微调。

关键点：三层是**依赖链**——上层缺输入就不该往下硬推。这也解释了为什么"先定每周多重"通常问错了层级。

## A1 — 案例 / 演练 (Application)

原书以 **Table 22.1** 给出三级对应关系、以 **Figure 22.8** 给出该流程的成品（女性篮球运动员年度计划样例），但**未就"三级建立流程"单独提供带输入的演练**。以下为**明确标记的合成演练**，只演示流程、不冒充书中案例。

- 输入：某大学足球运动员，单赛季（8 月–12 月），已知竞赛日程与主项目标；**缺训练状态数据**。
- 执行：
  1. 一级——按日程把训练年切成 off-season / preseason / in-season / postseason；依原书"单赛季项目年度计划即 1 个 macrocycle"，定年度 = 1 个 macrocycle。
  2. 二级——因缺训练状态**停在此**；补齐"中高级 + 赛程密集"后判为 emphasis。
  3. 三级——列出抗阻 / plyo / 专项的 modes 与 microcycle 负荷结构。
- 输出：得到"1 macrocycle + 4 时期 + 所选模型 + 各期 modes"；缺训练状态时只交付到一级并标注缺失输入。（原书未说明该演练的实际训练结果。）

## A2 — 未来触发 (Trigger)

**用户会在什么情境下遇到这类问题**
1. 用户要"把一年的训练排成计划"，却把"周期化"和"写一份计划"当成一回事。
2. 用户问"periodization 和 programming 到底有什么不同"。
3. 用户想先改某一周的负荷，却用"周期化"来称呼这件事。
4. 用户面对一个新赛季，不知道要先定框架还是先定每周内容。

## E — 执行 (Execution)

**输入契约**
- 必需：竞赛日程（日期区间，格式 YYYY-MM-DD）、项目为单赛季或多赛季（决定年度含几个 macrocycle）。
- 可选但显著影响结果：训练状态（beginner/intermediate/advanced）、主项需求分析结论。
- 缺失处理：**无赛程不得静默编日期**，先询问；**无训练状态可完成一级，二级暂缺并标注**——不得猜测档位。

**步骤**
1. **一级 periodization**：按竞赛日程把年度计划切成 periods/phases，标出年度含几个 macrocycle（单赛季=1、大学田径室内外=2、三项运动员=3）。完成标准：得到"含日期区间的框架 + 每个 block 有目标名（hypertrophy/basic strength/strength-power/peaking 等）"。
2. **二级 planning**：据训练状态与赛程密度选 parallel / sequential / emphasis（判定规则见 `cap.nsca.periodization-model-choice`）。完成标准：写出"所选模型 + 依据"；若训练状态未知 → **停在此**并输出待补输入。
3. **三级 programming**：把模型与各 period 对齐，落地 modes（如抗阻/plyo/专项）、methods 与负荷结构（强度、量、负荷模式）。完成标准：每个 block 均有 modes 与负荷结构。

**判停点**：步骤 2 遇"训练状态缺失"→ 停在步骤 1，交付"框架 + 待补输入"，不猜。
**输出契约**：三层交付物清单——(1) 时期/阶段框架（含日期）；(2) 选定模型 + 依据；(3) 各期 modes/负荷结构。原书未规定统一的落地表格样式，本卡输出的结构为**约定**。

## B — 边界 (Boundary)

- **不要用**：只做单次课或单周微调（那属 programming 层，无需跑三级流程）；无竞赛日程的健康健身人群。
- **作者警告的失败模式**：periodization 与 programming 被**混用**，是科学与实践文献中的核心混淆（ch22 开篇）。
- **作者盲点（BOOK_OVERVIEW 步骤 3）**：变量强耦合（3.3-3），分节叙述会诱导线性思维——三级骨架不可当作"变量各自独立"。
- **相邻易混**：`cap.nsca.periodization-model-choice`（选模型）、`cap.nsca.annual-plan-construction`（排年度）、`cap.nsca.periodization-cycle-durations`（定周期时长）。
